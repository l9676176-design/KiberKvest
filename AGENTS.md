# KiberKvest: правила продолжения

## Источник требований

- `docs/research.md` — исследование, сценарии десяти миссий и утверждённые визуальные требования.
- `docs/brief.md` — обязательный пошаговый план, экраны, переходы и критерии готовности.

## Границы

- Перед изменениями получить актуальную ветку `main` и проверить чистоту рабочей копии.
- Работать только внутри папки проекта.
- Не устанавливать зависимости: приложение использует HTML, CSS, JavaScript и встроенный Node.js test runner.
- Не добавлять регистрацию детей, чат, рейтинги, платежи, Telegram как обязательную платформу или генеративный ИИ.
- Не публиковать проект и не отправлять его в GitHub без отдельного разрешения владельца.
- Не заменять утверждённые изображения без отдельного согласования.
- Не коммитить секреты, персональные данные, временные файлы и локальные настройки.
- После изменений обновлять относящиеся к ним документацию, статус и историю.

## Команды

- Все тесты: `npm test` или `node --test tests/*.test.mjs tests/*.spec.mjs`.
- Сборка: `powershell -ExecutionPolicy Bypass -File scripts/build-offline.ps1`.
- Исходная версия: `npm start` или `node scripts/server.mjs`.
- Собранная версия: из `dist` выполнить `node server.mjs`.

## Обязательный порядок исправления ошибок

Этот раздел действует только внутри репозитория KiberKvest (проект «Гиберквест»)
и только для задач по поиску и исправлению ошибок. Он не распространяется на
другие проекты владельца.

Перед исправлением ошибки обязательно использовать проектные навыки в таком
порядке:

1. `.agents/skills/systematic-debugging/SKILL.md` — воспроизвести ошибку и найти
   первопричину до изменения кода.
2. `.agents/skills/test-driven-development/SKILL.md` — сначала создать проверку,
   которая воспроизводит ошибку и падает по ожидаемой причине.
3. `.agents/skills/playwright/SKILL.md` — проверить пользовательский сценарий в
   настоящем браузере, если ошибка относится к интерфейсу, нажатию, состоянию,
   звуку, переходу или опубликованной версии.
4. `.agents/skills/requesting-code-review/SKILL.md` — проверить изменение на
   соответствие исходной задаче и отсутствие побочных нарушений.
5. `.agents/skills/verification-before-completion/SKILL.md` — провести свежую
   итоговую проверку перед словами «готово» или «исправлено».

Наличие класса CSS, изменение массива состояния и прохождение модульного теста
не доказывают исправление интерфейса. Для ошибки интерфейса обязательна проверка
точного сценария пользователя в браузере. Если опубликованная версия входит в
задачу, проверяется именно она, а не только локальный исходный код.

Навыки не разрешают публикацию или отправку изменений в GitHub без отдельного
разрешения владельца.

## Структура

- `src/` — исходное PWA-приложение.
- `tests/` — проверки данных и поведения без сторонних библиотек.
- `dist/` — готовая статическая сборка.
- `downloads/KiberKvest-offline.zip` — автономный школьный пакет после сборки.
- `docs/` — документация, бриф, исследование и архитектурные решения.
- `.agents/skills/` — проектные навыки диагностики, тестирования, проверки кода
  и браузерной проверки ошибок «Гиберквеста».
